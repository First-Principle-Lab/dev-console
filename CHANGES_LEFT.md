## Merge blockers

- [ ] **Respect the manual vault lock when revealing the recovery credential.** [`recovery_key` in `ipc.rs`](https://github.com/parththirwani/dev-console/blob/7213142997a397d16d2259eb654d55f754bbb5ab/src-tauri/src/ipc.rs#L524-L537) checks only the window label, then returns the credential that decrypts every backup. Require an unlocked vault in the Rust handler. Update the [browser IPC mock](https://github.com/parththirwani/dev-console/blob/7213142997a397d16d2259eb654d55f754bbb5ab/tests/e2e/ipc-mock.js#L275-L281) only after the backend matches its locked-vault behavior. Add a native IPC test that locks the vault, calls `recovery_key`, and proves the credential is not returned until authenticated unlock.

- [ ] **Remove a revealed recovery credential as soon as the vault locks.** [`SettingsPanel.svelte`](https://github.com/parththirwani/dev-console/blob/7213142997a397d16d2259eb654d55f754bbb5ab/src/components/SettingsPanel.svelte#L141-L154) keeps the credential in component state. A focused Chromium check confirmed it remains visible after a `vault-state-changed` lock event. Subscribe to vault state while Settings is open; clear the credential and copied state on lock. Test both locking with Settings open and closing/reopening Settings.

- [ ] **Copy the recovery credential through the protected native clipboard path.** The current `navigator.clipboard.writeText` call bypasses the configured expiry and lock clearing used for saved secrets. Add a narrow backend copy action that verifies vault access, uses the native clipboard expiry, and clears its owned copy on lock. Confirm that an unrelated clipboard value copied afterwards survives expiry or lock. Keep the credential out of logs and UI notifications.

- [ ] **Make archive replacement recoverable after process interruption.** [`apply_archive`](https://github.com/parththirwani/dev-console/blob/7213142997a397d16d2259eb654d55f754bbb5ab/src-tauri/src/state.rs#L88-L128) writes the encrypted vault before the SQLite command transaction. Its rollback covers ordinary errors but cannot run if the process stops between those writes. Add durable recovery state, with a shared operation ID or equivalent way to tell on startup whether the SQLite commit happened. Do not expose the library until recovery has finished. In a disposable profile, terminate the process before and after the SQLite commit, restart, and assert that commands and secrets belong to the same complete version. Keep recovery files encrypted and private.

## Functional and UI fixes

- [ ] **Load Settings while the vault is locked.** [The initial `Promise.all`](https://github.com/parththirwani/dev-console/blob/7213142997a397d16d2259eb654d55f754bbb5ab/src/components/SettingsPanel.svelte#L169-L180) rejects when listing secrets fails, leaving General controls at "Loading..." indefinitely. Load settings and app state independently of secret counts. Show no secret count while locked, then refresh it after unlock. Add a browser test that opens Settings in a locked profile and can change and save a general setting.

- [ ] **Guarantee a normal export never replaces an existing file.** [`write_private_mode`](https://github.com/parththirwani/dev-console/blob/7213142997a397d16d2259eb654d55f754bbb5ab/src-tauri/src/backup.rs#L434-L479) checks `path.exists()` before `rename()`. A file created between those operations can be overwritten without confirmation. Use an atomic no-replace publish operation for `allow_overwrite = false`; keep the explicit overwrite route separate. Test a competing destination creation and confirm its bytes stay intact.

Increase body/help text size and spacing, especially for recovery and import warnings.
